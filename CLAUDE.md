# CLAUDE.md – Zappen durch die Zeit

Product name „Zappen durch die Zeit“; „Was lief damals?“ is the tagline. Repository `zappen-durch-die-zeit`, domain `zadudize.de` (**Za**ppen **du**rch **di**e **Ze**it). Internal names use the prefix `zdz`: `@zdz/*` packages, `zdz-*` browser storage keys, `zdz_admin` cookie, `ZDZ_*` variables.

Start by reading `ARCHITECTURE.md`. M1 and M2 (database + seed import) are done. Days in the DB: 13.03.1991 (tvprogramme.net), 02.05.1997 and 01.12.1997 (tvprogramme.net), 20.11.1998 (own reconstruction), 18.01.1999 (tvprogramme.net, 4 channels only). Plus 369 further 1990s days imported locally from the tvprogramme.net preservation copy (`pnpm ingest import archive`, part of `db:setup`; data in git-ignored `.data/archive/tvprogramme.net-seed/`, regenerated by `.data/archive/tvprogramme.net-data/to_seed.py`). The same script derives an **assumed programme** for the remaining 1990s dates (completeness `series_only`): a slot seen ≥4 times (channel, start, weekday pattern; holiday weeks ignored) is filled in only between two sightings in that same slot, at most 400 days apart, never on holidays. Assumed days are marked on the TV and never used as start/best/random days.

## Commands
- `pnpm db:setup` – apply migrations and import `seed/*.json` (stop `pnpm dev` first: the local PGlite DB is single-process).
- `pnpm dev` – web app on http://localhost:3000 (reads from the DB).
- `pnpm lint`, `pnpm test`, `pnpm typecheck`, `pnpm build` (CI runs all four); `pnpm format` (Prettier) only on files you change anyway. Data formats and curation: `docs/DATA.md`.
- `pnpm ingest sources` – list schedule sources and their `license_status`.
- `pnpm --filter @zdz/db generate` – new migration after editing `packages/db/src/schema.ts`.
- Local DB: PGlite in `.data/pglite` (no server needed). Set `DATABASE_URL` to use a real Postgres instead.
- `pnpm ingest set-license <status> <source-name-part> -- <notes>`, `pnpm ingest remove-source <name>`.
- Community contributions: one free-text field plus optional files at `/mitmachen` (core `classifySubmission` sorts it into video link / schedule / note), sent to the route `/mitmachen/senden` (not a server action: origin check, body capped at 26 MB before reading, global upload quota), moderation at `/admin/beitraege` (needs `ADMIN_TOKEN`; set `CONTRIBUTION_SECRET` for form tokens/IP hashing; both in `apps/web/.env.local`, git-ignored; all variables in `apps/web/.env.example`). Nothing a visitor submits goes live before approval; approved video links become `media_candidate` rows with `found_by = community`.
- `pnpm ingest purge` – retention (core `RETENTION_DAYS`: spam 30 d, rejected 90 d with files, e-mail 90 d after review, handled reports 180 d); also runs with `pnpm ingest snapshot`. Deletes real data: don't run it on the owner's database just to test.
- `pnpm ingest review-apply` – puts uploads the admin included at `/admin/aussortiert` into the seed files (then regenerate and re-import). The admin decides on the **server**, so first `docker compose run --rm jobs pnpm --silent ingest review-export > decisions.json` there, copy it over and run `pnpm ingest review-apply --decisions decisions.json` locally. Without `--decisions` it uses the local database, whose decisions may be older or missing – and it **removes** library entries of groups it doesn't see as included (11 Nov 2026: that would have dropped 27 Schmidteinander episodes). Check the „removed“ count before committing.
- Data updates with changed `seed/` files: push to `main`, wait for the image, `./update.sh` on the server, **then** `deploy/import-archive.sh` (the interstitials and curated days come from the image).

## M6 features (docs/archive/architecture-m6-zapping-features.md)
- Keys live in one place, `apps/web/lib/keymap.ts` (handler, help overlay H/?, Info page). Digits + Enter, L last channel, V fullscreen, T teletext overview P300, M sound, ↑/↓ and ←/→ zap. The panel has P−/P+ and a sound button; CRT look and TV sounds are admin site settings (`site_setting`), not switches on the TV.
- What the TV shows: tabs **Fernsehen** (modes Lückenlos / Wie damals / Programm frei wählen), the theme programmes **Kinderprogramm** / **Talk Shows** and the **Chronik** (core `seamless.ts`, `themes.ts`, `events.ts`; route `/tag/<date>/lueckenlos[?thema=|?ereignis=]`). Themes and Chronik allow picking any show; the end of a video goes on to the next show.
- Chronik: events in core `HISTORY_EVENTS` (only those with material; the full candidate list and status in `docs/EVENTS.md`). Selection is automatic (exact recordings of reporting shows in the event's window); „✗ Passt nicht zum Ereignis" files an `off_topic` report with the event, `/admin/meldungen` „Aus diesem Ereignis nehmen" writes `event_exclusion` (only that event). Deep link `?ereignis=<id>`.
- Deep links: `/tag/<date>?sender=<slug>&zeit=HH:MM&programm=<theme>` (core `parseShareParams`/`shareUrl`; 00:00–05:59 = night after the date). The address bar follows the TV via `history.replaceState`; link previews via `/og` (absolute URLs from `SITE_URL`).
- Day listing `/tag/<date>/programm` (print + SEO). Indexed only with env `PUBLISH_LISTINGS=1`, a permissive licence and a real (not assumed) day (core `listingIndexable`); `sitemap.ts` follows the same rule. `SITE_URL` sets the sitemap host.
- "Video defekt melden": table `media_report` (keyed by URL), `blocked_video` hides a video across re-imports. Auto-block only with ≥3 "unavailable" reports in 7 days and a failed health check (`lib/video-health.ts`). Moderation at `/admin/meldungen`.
- YouTube error 101/150 is usually YouTube's bot check („Melde dich an, um zu bestätigen, dass du kein Bot bist"), not a blocked video: it hits rarely watched uploads at random, per request and connection (measured 10 Nov 2026: the same video plays in one try and fails in the next; `youtube-nocookie` vs. normal embed made no real difference). The player retries twice (`YouTubePlayer` `REFUSED_ERRORS`), then the TV shows `YouTubeRefused` („Nochmal versuchen" / „Bei YouTube ansehen"); the automatic report carries „YouTube-Fehler <code>" and the server drops it when oEmbed says the video is embeddable. Many test loads of YouTube embeds from one connection make the check more likely – don't hammer YouTube from the owner's network.
- Interstitials: table `interstitial` (replaced `ad_break`; kinds ad_break, ident, announcer, trailer, sign_off, sign_on, test_card; `channel_id` null = pool, e.g. single 90s ad spots). Rules in core `interstitials.ts` (private: own ad break or pool spot → ident; ARD/ZDF: pool spot only 17:00–20:00 → ident → announcer before 19:58–20:15; sign-off after a last broadcast ending ≥ 22:00). Curated in `seed/interstitials.json` (`pnpm ingest interstitials`, part of `db:setup`), moderation at `/admin/zwischenspiele`.
- TV sounds are synthesized (Web Audio, `apps/web/lib/sfx.ts`), no sound files.
- Admin (`/admin`): password `ADMIN_TOKEN` + TOTP code (`pnpm ingest admin-totp` writes `ADMIN_TOTP_SECRET` to `apps/web/.env.local` and prints the key for the authenticator app; `--print` only prints, for servers); in production both are required and the password needs ≥ 20 characters. Signed, expiring session cookie (`lib/admin-auth.ts`, `@zdz/core/totp`); failed logins and the last used TOTP step live in the DB (`admin_login_attempt`, `site_setting`): 5 per IP hash or 20 overall in 15 min lock the login; a code works once. Every admin page uses `AdminGate` and `AdminNav`; every action runs through `guarded()` (`lib/admin-action.ts`) and is used via `AdminForm` (errors inline, in German); destructive buttons use `ConfirmButton` (two-step „Wirklich?", no `confirm()`); lists page with `Pager` (`?seite=`).
- Dashboard `/admin`: key figures (real days; assumed days in a tile and trend of their own – most cartoon and series links live there), daily snapshots (`stats_snapshot`, also `pnpm ingest snapshot`, part of `db:setup`) as growth trend, TV switches (CRT look, sounds), recommendations for hidden stations (core `stationRecommendations`), per-station coverage with "Ausblenden" (`station_setting.hidden`: out of channel list, zapping and P300), date × station coverage matrix per year. Further admin pages: `/admin/gesperrt` (blocked videos, „Entsperren"), `/admin/aussortiert` (uploads the curation left out, `seed/upload-review.json`).

## Security & operations (docs/archive/change-request-2026-11-10-security-usability.md; running the site: docs/DEPLOYMENT.md, docs/OPERATIONS.md)
- Client address only via `clientIp()` (core `client-ip.ts`: `CLIENT_IP_HEADER`, else the X-Forwarded-For entry `TRUSTED_PROXY_HOPS` from the right). Never use the leftmost X-Forwarded-For value, and store addresses only as the daily hash.
- CSP with a per-request nonce in `proxy.ts` (core `csp.ts`); every page renders per request (root layout awaits `connection()`). A new external script, frame or media host must be added to `contentSecurityPolicy` and checked in the browser console (`CSP_REPORT_ONLY=1` to try).
- Production config is checked at start (`instrumentation.ts` → `lib/startup-check.ts`): no strong `CONTRIBUTION_SECRET` or no `SITE_URL` → the server exits. New variables go into `apps/web/.env.example` and the README table.
- Server actions keep the default body limit; large uploads only through a route that caps the body. Server-action arguments are untrusted: validate at runtime (e.g. core `parseReportInput`). Video reports are only stored for URLs we link (`isKnownVideoUrl`).
- Impressum/Datenschutz read `OWNER_*`; the Datenschutzerklärung describes what the code does – update it with any new storage key, cookie, provider or retention change.
- Dev server: after adding exports to `packages/*` restart `pnpm dev` (otherwise "… is not a function" from a stale module). Only one process may open PGlite: stop every `next-server` before migrations or a production test. Production refuses PGlite unless `ZDZ_PGLITE_DIR` is set explicitly (local production test: `ZDZ_PGLITE_DIR=$PWD/.data/pglite`). Headless browsers can't play YouTube (error 150) and so file automatic "unavailable" reports – keep that in mind when looking at `/admin/meldungen` after browser tests.

## Conventions
- TypeScript strict, pnpm workspaces (`apps/`, `packages/`, `workers/`).
- UI text in German; code, comments, commit messages in English.
- Times: always Europe/Berlin; TV day runs 06:00→06:00; use the helpers in `packages/core/src/time.ts`, never ad-hoc date math.
- Never download or re-host video or audio. Only store URLs/IDs and metadata.
- Use YouTube privacy-enhanced embeds (`youtube-nocookie.com`) behind a click-to-load consent overlay.
- Respect source licences: do not scrape fernsehserien.de or wunschliste.de (licence first).
- tvprogramme.net: `license_status` = `not_required` (sources and status: `/info`, `docs/DATA.md`). A preservation copy lives in `.data/archive/tvprogramme.net/` (git-ignored). The Info page credits the site; the TV itself shows no per-day source line.
- Match levels (colours in `apps/web/lib/labels.ts`): 🟢 `exact` = this very broadcast; 🟡 `same_show_period` (seed `same`) = same show from the same year *as aired on that channel*; 🔵 `same_show` (seed `sim`) = everything else — other episodes, other years, and the same event from another broadcaster or with other commentary/language (e.g. a CBC recording of an ARD sports broadcast); ❌ missing.
- Video links: a matching title is not enough. Check the uploader/channel and what the video actually is (one wrong link spreads to many days via reuse). Owner rule: **what aired on TV is linked, whatever its topic** – conspiracy/UFO shows included; **erotic programmes that aired are linked too** (owner decision 2026-11-11, replacing the 10 Nov rule to leave them out): Tutti Frutti, Playboy Late Night Show, Wa(h)re Liebe, announcements and trailers for them – they belong to the TV of the time like everything else; only real pornography (never aired on these stations) stays out; the uploader is checked only for whether the recording is genuine and from the right era. Exception: a right-wing channel that frames or comments the content and was active in the last 5 years → leave it out and put it on the review page (`seed/upload-review.json`, `/admin/aussortiert`). Material that never aired (lectures, rallies, internet shows, propaganda) is never linked. Still reject spam re-uploaders ("HD Watch HD Deutsch") and recordings from the wrong era. Then verify technically: YouTube via oEmbed; archive.org only if the file itself plays: items can look public while each file is `"private": "true"` (HTTP 401), e.g. the `tagesschau-20-clock-evening-news` mirror. Curated links for recurring shows live in `seed/media-library.json`.
- `docs/archive/prototype/index.html` is a design reference (colours, CRT look, teletext EPG, remote). Rebuild it as components; don't copy the inline script.

## Definition of done for M1
- `pnpm dev` shows the TV for 13.03.1991 with 6 channels and live clock.
- Tuning to a slot with a YouTube match plays inside the screen, seeked to the right offset.
- Mediathek matches show a link-out card; unmatched slots show the programme card + search link.
- Private channels show an ad-break overlay at programme boundaries.
- Unit tests for TV-day time math and slot lookup (incl. after-midnight broadcasts).
